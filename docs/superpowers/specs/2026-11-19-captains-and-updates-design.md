# Капитаны команд и автообновление

## Зачем

1. В командной игре сейчас отвечает каждый, и очки команды равны сумме очков. Ведущий хочет, чтобы за команду отвечал один капитан, а остальные помогали голосованием.
2. Архив с приложением ведущий раздаёт друзьям (около 10 человек на Windows и Mac). Новые версии должны доходить до них без повторной пересылки архива на 116 МБ.

## Капитаны

- **Переключатель.** На пульте «Отвечает капитан» доступен только в режиме «Команды». Если он выключен, всё работает как сейчас.
- **Назначение.** Ведущий назначает капитана кликом по игроку в карточке команды; капитана отмечает значок 👑. Сменить его можно когда угодно.
  - Если капитана нет, им становится первый игрок, попавший в команду.
  - Если капитан ушёл из команды, капитаном становится следующий её участник.
- **Ответ.** В вопросе засчитывается только ответ капитана, и очки начисляются команде. Бонус за скорость считается по времени ответа капитана. Личных очков у участников в этом режиме нет.
  - Ручные ± работают как сейчас.
  - Если ответ засчитан вручную на пульте, засчитывается ответ команды.
- **Голоса.** Остальные участники видят те же варианты A–D, но их нажатие считается голосом. Голос можно поменять, пока вопрос открыт.
  - Капитан видит возле каждого варианта число голосов, и оно обновляется вживую.
  - В вопросе со свободным ответом участники присылают свои варианты. Капитан видит их списком (одинаковые варианты сводятся в один, рядом их число) и может отправить любой вариант одним нажатием.
- **Пульт и экран.**
  - Галочка «ответил» появляется у команды, когда ответил капитан. На пульте видны и голоса.
  - Экран после показа ответа показывает распределение ответов по командам, а не по людям.
- **Сохранение.** Капитан, голоса и режим сохраняются в game-state и переживают перезапуск сервера. В CSV попадает одна строка ответа на команду.

## Автообновление через GitHub Releases

- **Репозиторий.** Код лежит в публичном репозитории ведущего на GitHub. Квизов и `data/` в репозитории нет.
- **Выпуск версии.** Версию задаёт `version` в package.json. Команда `npm run release` собирает `quiz-party-update-<версия>.zip` и выпускает GitHub Release с тегом `v<версия>` (через `gh`). Помимо этого архива, к релизу прикладываются его SHA-256 и полная переносная сборка.
  - В архиве: `src/`, `public/`, рабочие `node_modules/`, `server.js`, `package.json`, `package-lock.json`, `README.md`. Файлы запуска `start.bat`/`start.command` не обновляются: они выполняются во время обновления (решение при реализации). `start.bat` написан только латиницей: cmd неверно читает UTF-8 вокруг goto.
  - Node.js в архив не входит.
- **Проверка.** При запуске и по кнопке «Проверить обновления» сервер запрашивает `api.github.com/repos/<владелец>/quiz-party/releases/latest`. Если версия новее, на пульте появляется «Доступна версия X → Обновить».
  - Без интернета проверка тихо ничего не показывает.
- **Установка** (только с самого ноутбука, при этом игра не должна идти):
  1. Сервер скачивает архив и сверяет SHA-256.
  2. Распаковывает его во временную папку.
  3. Заменяет только перечисленные выше файлы и папки. `quizzes/`, `data/` и `runtime/` не трогаются.
  4. Завершается с кодом 42. `start.bat` и `start.command` в этом случае запускают сервер заново, и пульт переподключается сам.
- **Ошибки.** При любой ошибке старая версия остаётся рабочей, а на пульте выводится текст ошибки.

## Переносная сборка

- В архиве нет никаких квизов. Папка `quizzes/` создаётся пустой при первом запуске.
- В архиве есть зашитый адрес репозитория для обновлений.

## Подходы, которые отбросили

- **Облачная папка.** Подходит только для двух своих компьютеров: каждому другу пришлось бы давать доступ и ставить облачный клиент.
- **Приватный репозиторий с токеном.** Токен оказался бы в архиве у 10 человек, то есть фактически стал бы публичным.

## Решения, принятые мной (можно поправить)

- В режиме капитанов личных очков нет: очки получает только команда.
- Пока идёт игра, обновить нельзя.
- Проверка обновлений идёт при каждом запуске и вручную по кнопке; фоновой проверки нет.
